# DZ APP

A classifieds marketplace connecting the diaspora in France and Algeria.
This repo is the **MVP**, scoped to four categories (**Voitures** / cars,
**Immobilier** / real estate — both sale and rental, **Achat/Vente** /
general buy & sell, and **Emploi** / jobs) to prove out the product
before expanding to Mariage and the rest.

## Stack

- **Next.js 16** (App Router, TypeScript, Tailwind CSS)
- **next-intl** — French (default), English, Arabic (full RTL support)
- **Prisma** ORM + **Postgres** (hosted on [Neon](https://neon.com), free
  tier) — persists across redeploys, unlike the SQLite-on-ephemeral-disk
  setup this started on
- **Auth.js (NextAuth v5)** — email/password (Credentials provider, JWT
  sessions), with forgot/reset password via email
- **Invite-only signup** — registration requires a unique, single-use
  invite code minted by an existing user (the `/invites` page); see
  "Invite-only signup" below for how the very first account gets created
- **Resend** — password reset emails (free tier). Without an API key set,
  reset links are logged to the server console instead (fine for local dev)
- Uploaded images are served through `src/app/api/uploads/[...path]`, not
  Next's `public/` static pipeline — see that route's comments for why

## What's in the MVP

- Register / login, with show/hide password and forgot/reset password —
  registration requires an invite code (see "Invite-only signup" below)
- Browse Voitures (cars), Immobilier (real estate), or Achat/Vente (general
  goods) listings with filters (ville, pays, prix, plus category-specific
  ones — property type for Immobilier, item category/condition for
  Achat/Vente)
- Voitures and Immobilier listings can be tagged **à vendre** or **à
  louer** (rentals show price per day for cars, per month for properties);
  Achat/Vente is always a straight sale, tagged **neuf** or **occasion**
- Listing detail page with image gallery and real contact info (call /
  email buttons using the seller-provided contact name, email, phone)
- Post a new car, property, or general-goods listing (with photo upload)
- Ambiguous "Browse"/"Post an ad" buttons (home page, nav bar/footer
  outside a category) open a small category picker instead of guessing
  which of the three you mean
- Data model already includes `Conversation` / `Message` / `Favorite` for
  the next iteration (in-app chat, saved listings) — not wired to any UI
  yet; contact info on each listing is the way to reach a seller today

## Quickstart

### Option A — Deploy to Render (get a real URL)

This repo includes a [`render.yaml`](render.yaml) blueprint.

1. Click **[Deploy to Render](https://render.com/deploy?repo=https://github.com/samdayayd/samdayayd-dzapp)**.
2. Sign in with GitHub, connect this repo, pick the branch you're working on.
3. Click **Apply**. Render does the first deploy — it'll fail once, because
   `NEXTAUTH_URL` can't be known until the service exists.
4. Once the service has a `*.onrender.com` URL, open its **Environment**
   tab, set `NEXTAUTH_URL` to that full URL (e.g.
   `https://dzapp-xxxx.onrender.com`), save, and it redeploys automatically.
5. (Optional but recommended) Create a free [Resend](https://resend.com)
   account, grab an API key, and set `RESEND_API_KEY` in the same
   Environment tab so forgot-password emails actually get delivered.
   **Important:** the default sender (`EMAIL_FROM`, `onboarding@resend.dev`)
   is Resend's shared testing address — it can only deliver to the email
   address *your own Resend account* is registered with, not to real
   users. Without `RESEND_API_KEY` set at all, or with it set but still
   using that default sender for anyone else's address, the app's
   forgot-password flow still responds "email sent" (deliberately, so the
   endpoint can't be used to check which emails are registered) but no
   email actually goes out — check the service's Render logs for a
   `[mail]` line, which says which of the two happened. To send to real
   users, [verify your own domain in Resend](https://resend.com/domains)
   and set `EMAIL_FROM` to an address on it (e.g. `DZ APP <noreply@yourdomain.com>`).
6. Visit the URL — register an account and post a listing.

### Emergency admin password reset

If someone's locked out and forgot-password email isn't working yet (step
5 above not done, or Resend itself is down), you can reset their password
directly, bypassing email entirely:

```bash
curl -X POST https://<your-service>.onrender.com/api/admin/reset-password \
  -H "Content-Type: application/json" \
  -H "x-admin-secret: <value from ADMIN_RESET_SECRET in the Environment tab>" \
  -d '{"email": "someone@example.com", "password": "a-new-password-at-least-8-chars"}'
```

`ADMIN_RESET_SECRET` is auto-generated by `render.yaml` on first deploy —
find the actual value in the service's Environment tab. The route responds
`501 ADMIN_RESET_NOT_CONFIGURED` if that variable is ever unset, so it's
never silently usable without it.

### Invite-only signup

Registration (`/register`) requires a unique, single-use invite code.
Anyone already registered can mint one from the **Invitations** page (in
the account menu, top right, or `/invites` directly — `POST /api/invites`)
and send it to whoever they want to let in; it's consumed the instant
someone signs up with it, so it can't be reused or passed further than
that one person.

**Bootstrapping the first account:** a brand-new database has zero users,
so there's no way to mint a real invite code — nobody to log in and
generate one. `BOOTSTRAP_INVITE_CODE` solves that: it's a second,
always-valid code that isn't tied to the database at all, so it works on
a genuinely empty database (first-ever deploy) with nothing else to rely
on. Auto-generated by `render.yaml`; find the actual value in the
service's Environment tab, use it once to create your own account, then
just ignore it — it never expires or gets consumed, so there's no need
to rotate it unless you suspect it's leaked.

Note: the database (Postgres on Neon) persists across redeploys — real
users and listings survive a `git push`. Uploaded photos don't yet; they
still live on the service's own ephemeral disk and reset on every
redeploy or restart. See `render.yaml`'s comments.

### Option B — run locally

```bash
cp .env.example .env
# generate a real secret and paste it into AUTH_SECRET in .env:
openssl rand -base64 32

npm install
npx prisma migrate dev
npm run dev
```

Visit http://localhost:3000.

## Project structure

```
prisma/schema.prisma          # User, Listing/ListingImage (cars), Property/PropertyImage (real estate),
                               # Item/ItemImage (general goods), Favorite, Conversation, Message,
                               # PasswordResetToken, InviteCode
messages/{fr,en,ar}.json       # all UI translations
src/i18n/                      # next-intl routing/config
src/auth.ts                    # NextAuth config (Credentials provider)
src/app/api/register           # sign-up endpoint (requires an invite code)
src/app/api/invites            # mint/list invite codes (requires login)
src/app/api/forgot-password    # sends a reset link
src/app/api/reset-password     # consumes the reset token
src/app/api/listings           # create car listing endpoint
src/app/api/properties         # create property listing endpoint
src/app/api/items              # create general-goods listing endpoint
src/app/api/jobs               # create job listing endpoint
src/app/api/upload             # image upload endpoint (shared by all categories)
src/app/api/uploads/[...path]  # serves uploaded images (see comments there)
src/app/[locale]/voitures      # cars: feed, detail, create-listing pages
src/app/[locale]/immobilier    # real estate: feed, detail, create-listing pages
src/app/[locale]/achat-vente   # general goods: feed, detail, create-listing pages
src/app/[locale]/emploi        # jobs: feed, detail, create-listing pages
src/app/[locale]/invites       # invite code list + "create a new code"
src/app/[locale]/login, /register, /forgot-password, /reset-password
src/components/CategoryDropdown.tsx  # the "which category?" picker used on ambiguous CTAs
```

  redeploy even though the database (now Postgres) no longer does
- Phone/ID verification badge
- Additional categories: Mariage, Services
- Saved searches + alerts
- Admin/moderation dashboard
